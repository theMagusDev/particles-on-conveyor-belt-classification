## Модель и выбор весов

| Параметр | Значение |
| --- | --- |
| Конфигурация и архитектура | `r3_normalized`, ShapeCNN с нормализацией яркости каждого изображения |
| Размер входа | 64×64 |
| Все параметры | 607 976 |
| Инициализация весов | Случайная, без предобучения |
| Seed итогового запуска | 17 |
| Число эпох и выбранный checkpoint | 36 эпох с нуля, checkpoint эпохи 30 |
| Macro-F1 на validation | 1.000000, 480 верных ответов из 480 |
| Macro-F1 на публичной части теста | 1.0000 на 320 изображениях. Закрытая оценка рассчитывается по другим 640 изображениям |
| Обучение с валидацией | 62.94 с, одна Tesla T4, AMP |
| 960 предсказаний | 53.70 с, CPU FP32, включая чтение изображений и запись CSV |

Веса обучались на 1880 изображениях train. Выбрали checkpoint с максимальным Macro-F1 на validation, при равенстве — с минимальной кросс-энтропией. Четыре конфигурации дали одинаковый Macro-F1 на исходных изображениях во всех трёх запусках с seed 17, 27 и 37. Итоговая конфигурация заняла первое место по результатам проверок с инверсией яркости, снижением контраста и размытием.

К изображениям train случайно применялись горизонтальное отражение (50%), аффинное преобразование с поворотом от −180° до 180°, масштабом 0.90–1.10 и сдвигом до 3 пикселей (75%) и инверсия яркости (50%). На всех этапах изображение переводится в оттенки серого. Из яркости вычитается среднее по изображению, затем результат делится на среднеквадратичное отклонение с нижней границей 0.05.

Исходная SmallCNN и схема выбора лучшей эпохи основаны на стартовом шаблоне соревнования. В проекте реализованы ShapeCNN для входа 64×64, сравнения архитектур и преобразований, анализ ошибок и проверка экспорта. В отдельном сравнении использовались официальные ImageNet-1K V1 веса ResNet18 из torchvision. [Материалы соревнования](https://www.kaggle.com/competitions/parts-on-conveyor-semenov/data) · [Документация ResNet18](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.resnet18.html)

В разделе «Итоговые результаты и решение» сохранены таблицы запусков, кривые обучения, матрицы ошибок и метрики по классам. В разделе «Анализ ошибок и вычислительная стоимость» разобраны конкретные ошибки baseline и итоговые затраты. [Ноутбук](solution.ipynb)

Из корня репозитория с установленным `uv` и данными `parts-v2` в каталоге `data/`.

## Обучение с нуля

На Kaggle откройте `solution.ipynb`, подключите исходный набор `parts-v2`, выберите GPU и выполните **Save & Run All**. По умолчанию на Kaggle запускается третья серия в режиме `full`. На другом пути к данным задайте `PARTS_DATA_ROOT` в первой ячейке. Результат сохраняется в `/kaggle/working/parts-v2-full/round3`.

Локальный запуск третьей серии на CPU из корня проекта в PowerShell.

```powershell
uv sync --locked --group notebook
$env:PARTS_DATA_ROOT = "data"
$env:PARTS_RUN_MODE = "full"
$env:PARTS_ROUND = "3"
uv run --locked --group notebook python -m nbconvert --to notebook --execute --ExecutePreprocessor.timeout=-1 --output solution.executed.ipynb solution.ipynb
```

Для запуска всех серий задайте `PARTS_ROUND=0`. Для опыта с ResNet18 без сети укажите путь к `resnet18-f37072fd.pth` в `PARTS_RESNET_WEIGHTS_PATH`. Результаты повторного обучения на CPU и GPU могут различаться.
